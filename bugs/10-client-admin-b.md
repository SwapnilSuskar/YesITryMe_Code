## client/src/components/Admin/ProductManager.jsx

- [HIGH] L85 (CONFIRMED) `fetchProducts` calls `/api/products` without `page` or `limit`, the server (`getProducts`) defaults to `limit = 10`, and the component reads only `response.data.data` with no pagination UI. Impact: as soon as there are more than 10 products the admin sees only the 10 newest, and older products cannot be edited or deleted from this screen. Fix: send an explicit large `limit` or add paging controls driven by `response.data.pagination`.
- [MEDIUM] L80 (CONFIRMED) Every keystroke in the search box changes `filters.search`, which re-runs `fetchProducts` and sends the text as `search`, which the server applies as a MongoDB `$text` whole-word search; the client then filters again by substring at L258-260. Impact: typing part of a word (for example "pho" for "Phone") returns zero products from the server, so the list goes empty while typing, each keystroke flashes the loading spinner, and a slow earlier response can overwrite a newer one. Fix: do not send `search` to the server (filter locally on the loaded list) or debounce and use a regex search on the server, and ignore out-of-date responses.
- [LOW] L177 (CONFIRMED) `validPricing` is serialised as-is, including each option's `features` array, which starts as `['']` and is never cleaned of empty strings. Impact: a package saved without typing a feature is stored with one empty feature, which renders as a blank bullet wherever features are listed. Fix: map `validPricing` to strip empty or whitespace-only entries from `features` before `JSON.stringify`.
- [LOW] L904 (CONFIRMED) The price `onChange` stores `parseFloat(e.target.value) || ''`, which turns the number 0 into an empty string. Impact: a price of 0 cannot be entered (the field clears itself), and typing a price that starts with "0" such as 0.50 wipes the field after the first character. Fix: keep the raw string in state (`e.target.value`) and convert to a number only in `handleSubmit`.
